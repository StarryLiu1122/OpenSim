# 推演审阅与专家反馈

本功能服务于“外部世界模型预测 → 虚拟街区检视 → 人类反馈”的单场景实验。预测点由 `services/WorldModelExperiment.cjs` 通过权威服务的标准命令提交。客户端工作台的 **推演审阅** 页会列出当前视野内名称以“预测点 · ”开头的对象。选择后可定位、填写“待核查 / 与现场一致 / 与现场不符”和最多 500 字的证据说明。

点击“保存这条审阅”后，记录写在当前客户端的用户数据目录。点击“导出专家审阅 JSON”取得 `region-lab.expert-review` 文件。记录包含预测点的持久对象 ID、位置、场景修订、持久实例 ID、区域 ID、服务 epoch、账户 ID、审阅者位置和 UTC 时间。预测点的模型名称、来源、真实坐标和原始输入哈希在实验工具生成的 `experiment.json` 中；客户端审阅记录通过对象 ID 与之关联。

在仓库根目录运行：

```powershell
node services/MergeExpertReviews.cjs --experiment=实验目录/experiment.json --reviews=expert-reviews.json --output=joined-reviews.json
```

合并器严格核对持久 `world_instance_id`，再检查区域、对象 ID、名称、展示位置和修订，汇总三种判断，并把两个输入文件的 SHA-256 写进结果。两个独立实例即使使用同一场景和批次，也不能合并彼此的审阅。若同一实例的服务重启，epoch 会变化；合并结果明确标记该差异，审阅者须核对持续存在的预测点和场景版本。旧版没有实例 ID 的审阅记录不能进入新版合并器。审阅文件保存在客户端，可被持有人编辑；账户 ID 是审计线索，不是加密签名或服务端证明。

**解释边界**：青色几何体是为了在摄影测量网格上方看清楚预测点而抬高的展示标记。`experiment.json` 的 `region_position` 才是外部水位输入映射后的坐标；`visual_marker_position` 是展示坐标。单个水位点不能推断道路封闭、街区积水范围或水动力学结果。提供的 Helsinki 水位文件是合成测试数据，不是现场监测值。当前版本也尚未实现模型回调、科学推演、服务端专家签名或确定性实验重放。
