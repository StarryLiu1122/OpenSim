# V4 存储合同：区域事务、内容与可搬移恢复

日期：2026-09-16。状态：0.4.2 已实现。替代 [早期草案](storage-v4-draft.md) 中的待决事项。运行步骤见 [RegionStore 指南](../../services/README.md)，选型见 [ADR 0001](../adr/0001-v4-storage.md)。

## 1. 层次、实体与版本

`WorldService` 接收可替换仓储，默认 `SnapshotRepository`，可选 `SqliteRepository`；两者提供 path、exists、load_world、save_world。桌面不直接访问 SQL 表。SQLite 适配器调用受控本机 RegionStore CLI；资产发布、事务、包导入/导出作为独立管理操作实现，不向普通世界命令开放文件系统写入。

| 实体/表 | 持久语义 |
| --- | --- |
| regions | 区域 UUID、owner、世界 revision、存储 commit_revision、epoch、环境/地形等根记录 |
| groups | 独立组 UUID、root_id、owner、组变换及原数组顺序 |
| objects | 部件 UUID、可空 group_id、asset_id、owner、局部变换及状态 |
| assets | 区域内资产元数据、顺序；网格引用不可变 SHA256，记录中不含二进制 |
| contents | SHA256 与内容字节数；同摘要跨实例复用 |
| commits | 区域/request_id、候选指纹、已提交存储号与 epoch；与世界记录同事务提交 |

区域/组/成员/资产使用复合外键，组的根与成员相互引用使用可延迟外键；提交点不存在悬空关系。完整归属、ID、变换及资产规则由原生 WorldSchema 检查。内容文件位于 `objects/<sha256>.glb`。Godot 节点、网络会话、物理句柄不写入世界记录。库存条目未来单独建模，不能用 assets 表冒充用户库存。

版本分别为：应用 **0.4.2**；世界 **3**；本地命令 **1**；JSON 快照 **1**；SQLite schema **2**；ZIP bundle **1**；FP **0.2**。外置二进制没有改变世界语义，因此不提升世界版本。

## 2. CLI 合同

调用 `RegionStore.exe request.json new-response.json`。输入/响应路径必须不同，响应必须是新文件。公共请求字段为 operation、root；区域操作需 region_id；涉及世界校验还需本机可信 godot 与 project 路径。数据 JSON 不会被解释为脚本，不从包中加载 Godot 原生资源或执行代码。

| 操作 | 额外输入 | 成功结果 |
| --- | --- | --- |
| init | 无 | 空库初始化或 1→2 迁移；返回 schema/SQLite 版本 |
| status | 无 | 区域 ID、commit_revision、epoch |
| load | region_id、校验器 | 完整世界、存储号、epoch；任一必要内容无效则整次失败 |
| save | input、expected_commit、request_id | 候选校验后提交完整区域；返回新存储号/epoch，幂等重试返回原结果 |
| export / backup | output、region_id、校验器 | 一个一致提交点的自包含包、SHA256 与源提交号 |
| import | input、expected_commit、request_id、校验器 | 验包、补齐内容、原生校验后提交，产生新 epoch |
| gc | 无 | 在全库引用集与写锁保护下删除未引用内容及暂存文件 |

请求和完整候选各 ≤8 MiB，单 GLB ≤2 MiB，最多 16 个导入资产；这些限制保持 V3.1 验证范围。默认桌面区域 UUID 固定；CLI 可存其他合法区域，当前桌面实例仍显示一个区域。校验进程最长 30 秒；数据库锁等待 3 秒。日志与工具缓存不进入导出包。

## 3. 提交确认与失败

1. 有界读取并拒绝重复 JSON 键，使用 Godot 生产规则验证候选；失败不写世界记录。
2. `BEGIN IMMEDIATE` 获取写事务，先查持久 request_id；同指纹返回原提交，异指纹拒绝。
3. 在同事务内比较 expected_commit：区域不存在为 -1，首次成功为 0，以后每次加 1。它独立于用户撤销/重做和世界内部 revision。
4. 校验每份内容摘要，写唯一暂存文件、flush、复核、原子发布；已存在同摘要文件必须重新验证。
5. 同事务写区域、资产、组、成员和提交记录；外键检查后 COMMIT。只有成功收到响应才由 WorldService 清除 dirty。

文件系统不参与 SQLite 回滚，发布内容后 SQL 失败可产生未引用文件，但不会产生新数据库引用。GC 与发布持有同一写锁，不能回收尚未完成事务的内容。读取/导出也在该锁内读取引用和字节，避免与 GC 交错；这是简单且保守的本机策略，会限制并发。

数据库持久提交与进程响应之间仍可能中断。调用方保留相同 request_id、候选和期望提交号重试，从 commits 表获知原结果。数据库提交失败、锁不可用、缺失资产、内容损坏均明确失败；不静默删对象或用占位资产宣称完整恢复。已提交内容之后被外部删除或磁盘损坏，加载将拒绝，需有效备份恢复。

数据库 `synchronous=FULL` 与文件 flush 是实现设置，当前证据覆盖写前/写中进程终止、提交后终止、不可用路径、实际写锁和内容损坏，不覆盖突然断电、网络磁盘或多机共享目录。

## 4. 迁移与兼容

schema 0 初始化，1→2 添加 epoch 与持久提交去重表，DDL 与版本号在一个事务内更新；故障回滚后可重试。未来版本明确拒绝。测试同时覆盖空库、已有区域/资产的升级、失败回滚与源世界保持。

JSON 格式 1/2/3 均先经过现有 SnapshotRepository/WorldSchema；读取不改源文件，迁移结果提交到指定数据库。当前格式保留原输入 JSON 数值，避免额外解析/序列化引入浮点微差。ID、组根与成员、顺序、资产元数据、材质、地形和门灯状态随区域恢复。

恢复历史包创建新存储 epoch，不能当作实时流的连续后继。V4 只有本机仓储；使在线客户端失效和重新订阅属于 V5 权威服务。OpenSim 原版数据库是独立对照实例，不与现代表结构合并。

## 5. Bundle 1 与备份恢复

ZIP 只允许 `manifest.json`、`world.json`、`objects/<64位小写sha256>.glb`。manifest 包含格式/版本、工具版本、区域 ID、源提交号/epoch、每个数据项的长度和 SHA256。world 保存资产元数据但不内嵌 GLB；全部登记的网格资产都带入，即使当前没有对象实例使用。

恢复不向任意路径解压：在内存中读取严格白名单项。压缩包 ≤16 MiB；2～18 项；解压总量 ≤16 MiB；单项 ≤8 MiB；manifest ≤64 KiB。拒绝路径逃逸、重复项、遗漏或多余项、区域 ID 不符、无引用内容、摘要/长度不符、未知版本及内嵌重复 GLB。补齐后完整世界仍须 ≤8 MiB 并通过原生校验。

导出先在事务中捕获和验证一致世界及全部字节，释放锁后写唯一临时 ZIP，再按恢复规则自检，最终原子发布新目标文件，不覆盖已有备份。它是**单区域逻辑备份**，不含数据库历史、回执历史、其他区域或账户。恢复时保存该包及校验结果，明确以哪个 source_commit 为恢复点；备份后的提交不在恢复范围。

升级前保留程序版本和可试恢复备份，在新目录升级副本；回滚使用升级前数据与对应程序，不在唯一数据上降级 schema。操作和错误码示例见 [管理指南](../../services/README.md)。
