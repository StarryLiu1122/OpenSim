# ADR 0004：V6 库存——按哈希引用内容的个人库存与导出包 v2

日期：2026-09-21。状态：已实施并经存储事务、端到端放置/授予和恢复验证。应用版本 0.6.0（V6-3 阶段）。

## 背景

V5 的资产只存在于世界内：上传即注册为世界资产，被对象引用，没有"用户持有但不在场景里"的概念。V6-3 要求库存条目、文件夹与授予，且库存、场景实例、资产内容三者分离。V6-1/6-2 已把账户与权限放进同一 SQLite；导出包 v1 不含任何服务表（已记录的限制）。

## 选择

| 候选 | 适用性与取舍 |
| --- | --- |
| 库存条目复制内容 | 语义简单但浪费存储，且破坏"多实例共享内容"的验证目标 |
| 库存作为世界 JSON 的扩展 | 世界格式要升版；库存与世界编辑共用 CAS 队列，互相阻塞 |
| **独立库存表按哈希引用内容（本轮选择）** | 内容保持哈希寻址、天然去重；库存操作独立于世界写队列 |

具体决定：

1. **schema 6**：`inventory_folders`（账户内树，父引用可延迟）与 `inventory_items`（`asset_sha256` 外键到 `contents`）。条目只记元数据（名称、许可、来源），不存字节。
2. **三者分离**：内容（`contents` + `objects/*.glb`）、世界资产（`assets` 行）、库存条目各自独立。放置（`PlaceInventoryItem` 命令）在世界内复用同哈希资产或导入一次；删除实例不动库存，删除库存不动场景。
3. **GC 修正（关键）**：存活集原来只看世界资产引用；纯库存内容会被误回收。现 `contents` 清理与文件回收都把 `inventory_items.asset_sha256` 计入存活集（有专项测试：仅库存引用的内容在 GC 后保留，移除引用后才被回收）。
4. **放置走命令队列**：`PlaceInventoryItem` 加入操作白名单，经同一 CAS 提交流程（需要时先 `ImportGlb` 再 `CreateObject`，同一候选世界内完成）；observer 在命令入口被拒，库存管理本身对所有角色开放（个人数据）。
5. **授予即转移**：`inventory_give` 把条目转给目标账户根目录（禁用账户拒收），不留副本；复制语义（copy/no-copy 权限位）留给后续版本。
6. **导出包 v2**：新增 `service.json`（账户、受限、授权、库存文件夹与条目；**不含**会话与审计）和纯库存引用的内容文件；清单版本 2。v1 包仍可导入（仅世界）。v2 恢复到空根时服务行与世界在同一事务落库，任何冲突整体回滚。这一并消除了 ADR 0002/0003 记录的"导出包不含身份/权限"限制。

## 后果与退出路径

- 库存管理经 `inventory` 包（fp 0.3 能力扩展），只操作本人库存；无管理员代管接口。
- 文件夹暂不提供删除操作（级联语义未定）；空文件夹可留待维护命令。
- 会话不进导出包：恢复后的实例由配置主体引导重新签发会话，这是有意边界（令牌属于运行期，不属于档案）。
- 库存条目引用的对象级授权（谁能看谁不能用）尚未存在；条目可见性=持有者本人。细粒度条目权限属后续工作。
- 未来可无痛加"条目复制"列或文件夹删除级联策略，表结构无需变。
