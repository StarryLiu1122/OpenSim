# ADR 0005：V6 智能体——受控接口与异步任务白名单

日期：2026-09-21。状态：已实施并经端到端任务生命周期与全部回归验证。应用版本 0.6.0（V6-4 阶段）。

## 背景

V6-4 要求平台能接入自动化客户端（脚本或 AI 智能体）：进入场景、观察世界、执行有限操作并回报结果。V5 的协议只有两条世界交互通道——化身 `input`（每帧控制量）与 `command`（全量世界操作白名单）。直接把这两条通道开放给自动化客户端等于给了一个无速率语义、无任务概念的编辑器账户，无法回答"这个动作做完了没有、失败了没有"，也无法按能力收口。

## 选择

| 候选 | 适用性与取舍 |
| --- | --- |
| 直接给智能体一个 editor 账户 | 零开发量，但能力面=整个人类编辑器，无法审计意图，也无任务完成语义 |
| 新增并行协议/端口 | 网关、鉴权、会话都要复制一份；两条权威路径难以同时维护 |
| **账户角色 + 专用包 + 任务白名单（本轮选择）** | 复用 V6-1 账户/会话/审计体系；能力面显式枚举；每个动作有状态机与回执 |

具体决定：

1. **schema 7：`agent` 账户角色**。`accounts` 表 CHECK 约束加 `'agent'`；SQLite 不支持改 CHECK，采用表重建迁移（事务外先 `PRAGMA foreign_keys=OFF`，重建后 `foreign_key_check` 验证再提交）。迁移失败回滚有专项夹具测试。
2. **角色封禁边界**：`agent` 角色在 `command` 入口与 observer 并列拒绝（`PERMISSION_DENIED`）、`input` 静默忽略、库存/权限/账户管理全部拒绝、`_can_permit` 恒 false。智能体不能通过任何既有通道绕过任务白名单。
3. **`agent` 包四个动作**：`observe`（只读投影快照）、`status`（任务查询）、`task`（提交任务）、`cancel`（取消任务）。observer 只能 `observe`/`status`——观察面对所有角色开放，行动面只给 agent 与普通编辑角色。
4. **任务白名单四类**：`move_to`（平坦移动，速度上限 6 m/s 由化身物理保证）、`set_state`（仅门/灯的 `active` 布尔）、`create_box`（内置立方体）、`update_object`（仅内置原始体，patch ⊆ {name, color}；导入网格一律拒绝）。载荷逐字段校验，数值参数有类型守卫。
5. **异步任务状态机**：`accepted → running → completed/failed/timeout/cancelled`。`move_to` 提交即 running，由服务器每帧驱动化身控制量；其余三类进入**同一 CAS 命令队列**（`origin:"agent"`），取出时才转 running——世界变更没有旁路，冲突、过期、校验失败都走既有路径并映射为任务失败。
6. **区域行为者委托**：演示世界的对象归区域行为者所有，而动态账户各有自己的 actor。任务内变更以区域 actor 执行（白名单本身就是全部能力），回执归属仍记智能体账户 id。这让"开门、开灯"这类对区域对象的操作成立，同时不扩大能力面。
7. **任务仅内存、不持久**：断线即放弃该客户端全部 accepted/running 任务（清队列、停化身）；任务表保留上限 200 条，只淘汰终态条目。重启后任务历史清空是有意边界——任务属于运行期，不属于档案。

## 后果与退出路径

- 智能体的世界变更与人工编辑共用回执/修订号体系，审计可归因到账户；但命令级 `origin:"agent"` 目前不进导出包（与既有回执边界一致）。
- 取消是协作式的：已取出执行（`active`）的任务会完成落库，但任务终态保持 `cancelled`，调用方能区分"世界已变"与"任务被取消"。
- `accepted` 状态的排队任务不参与超时扫描（队列通常即时排空）；若未来允许长队列，需要把 deadline 语义改为从提交起算。
- 任务无可编程组合（无脚本、无条件分支）；多步编排由调用方驱动，这正是 V6-5 端到端任务验证的形态。
- 未来可加任务类型（如 `place_inventory`）而不改状态机；加角色能力只需扩展白名单分支。
