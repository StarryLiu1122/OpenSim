# ADR 0006：V6 端到端智能体任务——编排形态与障碍恢复

日期：2026-09-21。状态：已实施并经端到端任务与回归验证。应用版本 0.6.0（V6-5 阶段）。

## 背景

V6-4 提供了单步任务白名单，但真实的智能体工作是**多步编排**："进入展馆、查询指定物体、操作门灯并报告结果"。这一步要回答两个问题：编排放在哪里（服务器内还是调用方），以及编排产物是什么形态（会话日志还是可审计文件）。验证中还暴露了一个物理缺口：演示区域的"无障碍"地板台阶高 0.22 m，化身没有跳跃输入的智能体会在台阶与墙缘的内直角处卡死（实测坐标 [131.81, 118.7]），直线行走无法完成"进入展馆"。

## 选择

| 候选 | 适用性与取舍 |
| --- | --- |
| 服务器内建任务编排器（脚本/序列） | 服务器要维护第二套控制流、持久化与调试面；与"任务仅内存"边界冲突 |
| **调用方编排 + 文件化审计产物（本轮选择）** | 白名单保持最小；编排逻辑由智能体侧自主演进；观察记录与动作回执落盘即可审计、可复现 |

具体决定：

1. **编排器 `services/AgentMission.cjs`**：库 + CLI 双形态。`AgentClient` 封装 agent 包（observe/status/task/cancel 与事件等待）；`runMission` 实现展馆巡检任务：出生点观察 → 开门 → 分段移动入馆 → 查询"室内展品" → 关/开"室内照明" → 终态确认。
2. **审计产物**：每次任务写 `observations.jsonl`（每条观察一行：标签、修订号、自身位置、按名查询命中）与 `receipts.json`（每个动作：task_id、终态、错误码、载荷细节、起止时间）。文件即交付物，人可审、 diff 可比。
3. **障碍恢复（服务器侧，仅 agent 任务）**：`move_to` 行走停滞（水平速度 < 0.3 m/s，提交后 0.6 s 宽限）持续 0.5 s 触发一次跳跃，跳跃间隔 ≥1.1 s。低台阶（0.22 m 地板、门槛）一跳即过；高墙（馆墙 4.2 m、关闭的门 3.2 m）仍然挡住，任务按截止时间超时——"关门不可入"的语义不变。
4. **可复现失败形态进测试**：关门进入→超时、长走→取消、重复 set_state→幂等完成、observer 驱动任务步→拒绝，全部作为独立场景断言。

## 后果与退出路径

- 障碍恢复只作用于 agent 任务驱动的化身；人类玩家的物理不变（六米/秒上限等既有不变量不受影响）。
- 跳跃恢复不是路径规划：复杂迷宫仍会超时，这是有意边界；未来如需导航，应在任务层加路径点规划而非加强恢复。
- 编排器是参考实现而非唯一客户端：任何能讲 agent 包的运行时都能复现同样任务。
- 产物文件不进导出包、不持久到存储层；它们属于运行期审计。

依据：[ADR 0005](0005-v6-agents.md)、[智能体合同 V6](../contracts/agents-v6.md)、[编排器](../../services/AgentMission.cjs)。验证：Test-AgentTask.cjs 18/18（任务全程、产物断言、人类客户端收敛、四类失败形态）、Test-Agent.cjs 50/50 回归（障碍恢复不影响既有语义）。
