# ADR 0002：V6 身份——SQLite 账户/会话、哈希令牌与帧内撤销

日期：2026-09-21。状态：已实施并经存储事务、端到端生命周期和重启持久性验证。应用版本 0.6.0（V6-1 阶段）。

## 背景

V5 的网络主体来自实例配置文件：令牌明文写在 `private-config.json`，主体只在服务器启动时读取，运行期不能新增、撤销或审计；成功回执虽按主体绑定，但"谁可以进入区域"本身没有持久管理接口。V6 第一阶段要为后续权限模型（V6-2）、资产库存（V6-3）和智能体受控接口（V6-4）提供可管理、可审计的身份底座。真实平台的账户系统、OAuth/OIDC 接口与运维条件仍未提供。

## 选择

| 候选 | 适用性与取舍 |
| --- | --- |
| 继续只用配置主体 | 无需迁移，但运行期不可管理、不可审计；无法支撑 V6-2 之后的授权粒度 |
| 独立身份服务（OIDC 等） | 需要额外进程、密钥与运维；真实平台接口未确认，本轮不引入 |
| **同一 SQLite 库扩展身份表（本轮选择）** | 账户、会话、审计与世界提交共用已验证的事务/迁移/备份机制；不新增服务进程 |

具体决定：

1. **schema 4**：`accounts`（唯一名称、actor 归属、角色、禁用位）、`sessions`（令牌 SHA-256 哈希为主键、签发/到期/撤销毫秒时间）、`audit_log`（只追加，毫秒时间、账户、动作、结果、≤2048 字符详情）。v3→v4 迁移在单事务内建三张表，注入故障可整体回滚（DDL 与 `user_version` 同进退）。
2. **令牌只存哈希**。存储层只接受 `^[a-f0-9]{64}$`；明文令牌仅在签发响应中出现一次，数据库、目录接口和审计均不持久化明文。
3. **服务器为时间权威**：存储操作的时间由请求方以 `now_ms` 传入，权威服务器统一取系统 UTC 毫秒；存储进程本身不读时钟，便于确定性测试。TTL 限 60 秒～30 天。
4. **`fp_version` 保持 "0.3"**，账户管理作为能力扩展（`type:"account"` 包 + `account_result` 回复），不升协议号。理由：不触碰 RegionHost 转发、桌面 `connection.gd`、Web 客户端和 V5 验收套件；未实现该扩展的旧客户端只是收不到管理功能，基础会话语义不变。此为显式取舍：扩展没有版本协商，客户端按 `UNSUPPORTED_ACCOUNT_ACTION` 等显式错误识别能力缺失。
5. **配置主体幂等引导**：启动时把 `config.principals` 落库为账户+会话；**无可用 owner 时首个配置主体提升为 owner**，保证全新实例必有可管理的根。已过期的配置令牌不落库、永不认证；未到期者按剩余时间（钳制到 60 秒～30 天）转为会话到期。
6. **内存注册表以存储为准**：服务器缓存账户/会话，但每个管理操作先写库成功才更新内存；重启从 `account_list` 全量重建。撤销/禁用在一帧内由 `_process` 的存活检查断开在线连接（1008/`SESSION_REVOKED`），禁用账户与撤销会话在同一事务内完成。
7. **RegionHost 转发关闭帧**：原网关在一侧关闭时直接 `Abort`，客户端只能看到 1006；改为转发关闭状态码与原因（10 秒宽限），使 1008/`SESSION_REVOKED`、`SESSION_EXPIRED` 等原因对浏览器与桌面客户端可见。

## 后果与退出路径

- 管理接口当前仅限 owner 角色；editor/observer 调用返回 `PERMISSION_DENIED`。更细的授权（V6-2）在此底座上扩展，不改身份表结构。
- 单写者 SQLite 限制不变；会话校验走内存注册表，不在热路径访问数据库。
- 审计日志当前无自动清理；`audit_list` 限 1–200 条、按插入序倒序返回。长期保留策略属于后续维护决策。
- 账户删除未提供（只有禁用）；actor 归属的级联语义留待 V6-3 资产库存定义。
- 备份/恢复自动涵盖身份表（同一 SQLite 文件）；但 V4 导出包格式（region-lab.bundle v1）只含世界内容，**不**导出账户/会话——跨机搬移身份需要复制数据库文件，此限制已记录。
- 未来接入平台级 OIDC 时，`sessions.token_hash` 可映射为外部访问令牌哈希，`accounts` 增加外部主体列即可，世界/回执数据不受影响。
