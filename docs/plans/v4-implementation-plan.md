# V4 原版融合与持久化实施计划

更新日期：2026-09-16。状态：V4.0～V4.2 已实现，逐项验证结果以 [执行记录](v4-progress.md) 与 [验收报告](../comparisons/v4-completion.md) 为准。前置版本：Region Lab V3.1 / 0.3.1。依据：[总体报告 A、客户端方案 B](../references/teacher/2026-09-15/README.md)、[目标对齐说明](platform-integration-alignment.md) 和 [总体路线](stage-one-rebuild-plan.md)。逐项状态与下一批顺序见 [V4 执行记录](v4-progress.md)。

V4 要解决三个具体问题：原版行为尚未实际对照，现有命令不能对接外部平台，文件快照尚不具备数据库事务和独立资产仓储。采用 V4.0 基线与契约、V4.1 原版最小网关、V4.2 数据库存储的顺序，完成后为 V5 权威区域服务提供可验证输入。

## 1. 范围与执行约束

本轮覆盖固定 OpenSim 独立运行、两部件对象组对照、浏览器导出预验证、一栋真实授权建筑、FP 合同、受控原版 Bot、Region 模块、仓储抽象、数据库和可独立恢复的导出包。

保持现有 Godot 4.5.1 标准版、GDScript、Jolt 与原版 C# 代码。原版插件以 C# 实现；现代服务与数据库语言在 ADR 中确定。当前运行世界格式 3、快照封装 1、命令封装 1 保持原有语义；新增 FP 使用独立版本字段。

本轮不实施双客户端权威同步、完整 SSO/库存、真实模型训练、完整 OAR 导入、WebGPU、GPU 物理、LSL 转译或大规模压测。这些能力在总体路线中有独立位置。Web 导出仅作能力探测，不提前交付浏览器编辑器。

所有任务由个人依次推进。测试创建唯一运行目录、区域 UUID、账户及端口配置，不使用用户默认世界。记录能复现结果所需的命令、版本、参数与日志；凭据不进入仓库。

## 3. 两部件对象组的最小行为案例

使用平地测试区域，设置两个 1×1×1 米部件：计划根部件位于 `[120,128,2]`，子部件位于 `[122,128,2]`，初始旋转为单位四元数。区域坐标均为 X 东、Y 北、Z 高。原版根选择规则必须由实际操作记录确认。

| 步骤 | 操作 | 必须记录与比较 |
| --- | --- | --- |
| C01 | 创建两个独立部件 | ID、归属、世界位置、旋转、尺寸、区域和存储字段 |
| C02 | 按明确顺序建组 | 实际根 ID、组身份规则、链接顺序、成员 ID 是否变化、局部偏移 |
| C03 | 整体平移 | 每个部件的世界位置增量，局部关系是否保持 |
| C04 | 恢复起始组位置，再绕区域 Z 轴旋转 90° | 在约定数学模型下，子部件应位于 `[120,130,2]`；对照旋转方向、乘法顺序及原版字段 |
| C05 | 调整子部件，随后统一缩放 | 原版子部件编辑及缩放规则；Region Lab 是否能表达；不能表达的形态单列 |
| C06 | 复制整个组合 | 新旧组和成员 ID、资产引用、归属、位姿及状态独立性 |
| C07 | 保存并关闭，重启读取组合 | 根和成员关系、局部变换、资产引用、有效状态；保留重启前后数据 |
| C08 | 解除组合，再保存并重启 | 世界位姿与成员 ID 保持；组关系清除；独立编辑和恢复正确 |
| C09 | 对组合施加非法或不允许操作 | 越界、跨归属、重复成员、错误根、无效旋转的结果；明确原版和原型允许范围差异 |

比较方法优先使用原版模块/存储记录和原型快照的结构化输出，辅以 Viewer 和原型截图。固定序列化精度后制定字段容差；V3.1 的具体测试容差只作参考，不直接宣称为两个物理引擎的误差保证。

完成后补充原型数据映射说明，并形成 `docs/comparisons/` 下的独立行为报告。报告同时注明 Viewer 版本、脚本引擎、物理后端、区域配置、样例坐标和完整操作顺序。

## 6. 存储合同必须回答的问题

### 6.1 实体与版本

区域记录保存区域身份、坐标/尺寸、环境、地形、修订与 schema。对象组记录保存独立组 ID、根 ID、世界变换和归属；成员记录保存局部变换、资产引用和行为状态。资产元数据、不可变二进制内容、对象实例与未来库存条目分别建模。

区分应用版本、世界 schema、数据库迁移版本、存储封装、FP 版本和实时流序列。外置资产可能只改变存储封装；只有世界语义变化才升级世界 schema。旧格式先按对应规则校验，读取不隐式改写源文件。

### 6.2 事务与修订

单区域候选世界是首轮事务边界，建组、复制和删除涉及的全部成员同时提交。数据库在同一事务中核对期望修订、修改记录、更新修订；禁止“先读修订、再无条件写入”。导入较大内容可先暂存，最终可见引用由事务发布。

当前本地撤销/重做继续形成新修订。历史快照恢复到网络运行世界时产生新世代，不把旧修订当成当前运行的连续后继。V4 预留此合同，V5 实现客户端失效和重订阅。

### 6.3 资产内容和导出

二进制以完整 SHA256 标识并验证，元数据登记来源、许可、尺寸和转换信息。先采用可替换的本地文件资产仓储；平台要求对象存储时通过同一合同接入。数据库事务不能自动覆盖文件系统或对象存储，必须明确发布顺序、重试和孤儿清理。

导出包包含版本化清单、世界数据、全部被引用的必要资产、摘要、生成工具版本和恢复说明。包必须可独立恢复，不能引用开发机绝对路径。归档解包检查路径、文件数、解压后大小、重复项和摘要；不执行包内脚本。

### 6.4 故障和一致性

必须定义保存确认的含义、数据库提交后的进程崩溃如何处理、备份捕获哪个一致性点、迁移失败后是否回滚或从备份恢复，以及缺失二进制时整次恢复拒绝还是受控占位。首轮正式恢复默认要求全部必要内容有效，不能静默删除对象。

要求记录一次正常保存、一次写入途中终止、一次二进制发布后数据库失败、一次损坏备份和一次完整离机路径恢复。进程终止测试只验证对应故障，不等价于断电持久性测试。

## 7. FP 契约与原型复用边界

| 当前入口 | 后续用途 | 必须新增的规则 |
| --- | --- | --- |
| GetRegionSnapshot | FP-01 初态 | 增量序列、快照边界、世代、主体可见范围 |
| 对象/组/地形/环境修改 | FP-06 | 服务端身份、批次、来源、冲突、幂等与回执 |

## 9. 风险与停止条件

| 风险 | 处理 | 不能据此宣称完成 |
| --- | --- | --- |
| 原版工具链或 Viewer 不兼容 | 锁定依赖，分离构建失败与连接失败；记录最小复现 | 只读源码或仅生成工程 |
| Region 模块线程与事件顺序不明 | 先只读观察，再验证场景调度和重入规则 | 网络线程直接修改成功一次 |
| Web 导出或 Jolt 行为受限 | 记录失败并验证后端/线程替代方案，修订导出合同 | 桌面运行通过或仅导出无错误 |
| 真实建筑超过当前限制 | 缩小授权场景或制作衍生低模，保留尺寸和转换证据 | 将原始样本重新命名为真实建筑 |
| 平台接口未提供 | 用固定 FP 样例与模拟端继续工程验证 | 标记真实世界模型已联调 |
| 数据库实现侵入现有逻辑 | 先提取合同，复用候选校验与既有样例 | 直接写表后仅查看对象数量 |
| 性能不足 | 记录热点和固定负载，单项优化后复测 | 提高输入上限或缩短采样来声称达标 |
