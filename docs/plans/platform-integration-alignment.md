# 平台目标与技术路线对齐说明

更新日期：2026-09-16。实现基线：Region Lab V3.1 / 0.3.1，提交 `1af88966496561787e79bb387083de998dae4a81`。本文是后续设计依据，尚未发布新的网络协议或改变当前世界格式。

本文将老师提供的总体报告和客户端方案转化为项目可执行的技术边界、接口任务和验收要求。来源编号 A、B 对应 [原件登记](../references/teacher/2026-09-15/README.md)，章节号沿用原文。后续版本安排见 [总体路线](stage-one-rebuild-plan.md)，近期执行项见 [V4 计划](v4-implementation-plan.md)。

## 1. 总体结论

项目最终交付应是世界模型平台的虚拟镜像试验场和人机协作入口。Region Lab 已完成的区域编辑、静态资产和持久化能力构成其基础，下一阶段需要补齐对外状态、事件、动作、回执和实验记录，使平台能够观察世界、执行任务并验证结果。

保留两条有明确边界的运行路径：原版 OpenSim 通过独立网关模块提供行为参考和兼容接入；现代区域服务向 Godot 客户端与智能体平台提供统一 FP 接口。每个世界由一个运行内核决定最终状态，跨运行内核迁移需要显式世界映射、数据转换和结果对照。

近期采用模块边界清楚的少量进程部署，先跑通单区域闭环；消息总线、微服务拆分、GPU 物理、联邦与云渲染均以场景需求和测量结果为进入条件。这一顺序适用于个人持续推进，保留原文远期方向。

### 3.1 指标之间的约束

B §9 的压缩引擎 25 MB 与首场景 15 MB 合计 40 MB，在理想 50 Mbps 链路下仅传输约需 6.4 秒（十进制单位），10 秒预算还需覆盖连接、编译、解码和首帧；因此必须分别测量冷缓存和热缓存。

1.5 Mbps / 20Hz 约为每次更新 9,375 字节，尚未扣除协议开销。1000 个实体若同时更新，平均不足 10 字节/实体，不能直接以 JSON 完整对象逐帧发送达标。应记录活动实体比例，先做 delta、AOI 与更新优先级，再评估二进制编码。

直接将区域绝对位置转为 float16，在 128～256 米区间的步距约为 0.125 米，不适合作为未经误差评估的通用坐标编码。V4 契约保留足够精度；后续比较局部原点、定点量化和误差预算。这些是由数值表示和指标计算得到的工程分析，不是已完成的性能实测。

状态到达、远程插值显示、本地预测反馈、动作受理与动作完成分别计时。100ms 插值缓冲与 120ms 本地视觉反馈目标使用不同测量对象；移动数秒的动作也不能要求其最终成功回执在 200ms 内完成。

### 4.1 契约中必须明确的字段

- 世界定位：`world_id`、`region_id`、`world_epoch`、`source_runtime`；原版 UUID、组 UUID、现代实体 UUID、平台 agent_ref 分别登记映射。
- 顺序与状态：持久化 `revision`、流 `seq`、`base_revision`、删除标记、快照边界；服务重启、实验重置与导入如何产生新世代。
- 时间：UTC 毫秒用于跨系统关联，逻辑 `tick` 用于仿真顺序，单调时钟用于时长；禁止用设备墙钟决定并发写入顺序。
- 动作：`command_id`、`trace_id`、主体、目标、能力、截止时间、前置修订、参数和版本；受理、执行中、成功、失败、超时、取消、结果未知的区分。
- 权限：认证后的会话决定主体，不能信任载荷自报的 `issued_by`；可见字段、写入能力、实验控制权分别校验。
- 内容：资产 SHA256、来源、许可、米制尺寸、清单版本；客户端通过资产标识访问，远程命令不能传入任意服务器文件路径。
- 模型数据：观测时间、预测有效时间、模型/数据集版本、单位、空间参考、置信或有效性标记；预测世界分支与实时世界区分。

### 4.2 权威状态与客户端分层

目标依赖为“表现层 → 只读 LocalWorldView”，“用户输入 → 命令客户端 → 权威服务”，“网络适配 → 状态同步器 → LocalWorldView”，“LocalWorldView → 渲染投影”。渲染代码不解析网络消息，网络代码不直接改场景节点。

本地离线模式继续通过 WorldService 修改世界；远程模式则提交给服务端同等校验入口。`LoadRegion` 导致修订回退、进程内 256 请求缓存和文件指纹检查都不能直接充当网络恢复合同。恢复历史快照应创建新世代，并使旧会话序列失效。

客户端可预测本地移动；对象编辑、开门、资产登记和实验状态由服务端确认后提交。发生断线时保留带过期标记的观察视图，并显式显示尚未确认的动作，重连后查询结果再决定重试。

## 5. 场景与交付证据

### 5.1 工程基准场景

先使用两部件组合、15 部件展馆和一栋真实授权小建筑验证身份、变换、碰撞、保存与恢复。每个场景保存原始来源、尺寸依据、资产摘要、版本、命令输入及预期结果。

### 5.2 首个科学场景

默认候选为“洪涝水位与道路阻断”，待老师确认业务优先级后固定。接收外部水位/淹没范围/通行状态时间序列，映射到显式场景字段；人类与 Bot 执行观察、到达和设施操作；专家标注错误；导出状态、动作与反馈。外部模型不可用时可用固定数据样本做工程验收，但真实平台联调状态保持未完成。

现有区域水平水面不代表真实洪水计算。V6.1 首轮只验收结果接入和任务闭环；栅格淹没边界、道路损毁、浮力、结构破坏等分别列能力范围。第二场景为交通调度或道路封闭绕行，复用协议与实验链路，以独立数据集验收。

### 5.3 三类复现

1. **记录回放**：恢复同一初态，按权威事件序列重建声明可回放的状态。定义规范化表示、状态摘要和差异报告，排除会话令牌等非世界字段。
2. **重新仿真**：相同输入重新执行物理或模型推理。固定版本、步长、随机源和外部响应，报告位置、时间及任务结果容差。
3. **反事实实验**：同一初态创建不同实验分支，修改明确变量，比较任务完成率、路径长度、违规次数和延迟；不能把变量差异归因于未控制的配置变化。

| 世界模型结果 | 坐标/高程基准、单位、时序、模型版本和数据授权 | V6.1 | 构建固定合法样例及不合法输入用例 |

## 7. 核实来源

- S1：[Godot 4.5 Web 导出](https://docs.godotengine.org/en/4.5/tutorials/export/exporting_for_web.html)，用于固定版本渲染、C#、线程和浏览器约束。
- S2：[MDN WebTransport](https://developer.mozilla.org/en-US/docs/Web/API/WebTransport)，用于浏览器端安全连接、流与数据报接口；实际浏览器矩阵以测试时版本记录。
- S3：[Khronos KTX-Software](https://github.com/KhronosGroup/KTX-Software)，用于 Basis Universal 转码与 Web/WASM 工具链说明。
- S4：固定本地源码 [区域归档写入](../../OpenSim/Region/CoreModules/World/Archiver/ArchiveWriteRequest.cs)、[区域归档读取](../../OpenSim/Region/CoreModules/World/Archiver/ArchiveReadRequest.cs)、[库存归档读取](../../OpenSim/Region/CoreModules/Avatar/Inventory/Archiver/InventoryArchiveReadRequest.cs)。
- S5：固定本地源码 [LoadRegionsPlugin](../../OpenSim/ApplicationPlugins/LoadRegions/LoadRegionsPlugin.cs)，加载区域数组并逐一创建场景。
- S6：固定配置 [OpenSimDefaults.ini](../../bin/OpenSimDefaults.ini)，`DefaultScriptEngine` 与 YEngine/XEngine 配置段。
- S7：固定本地源码 [GridServicesConnector](../../OpenSim/Services/Connectors/Grid/GridServicesConnector.cs)，表单构建及 XML 响应解析。

上述源码检查属于静态证据。原版插件生命周期、事件线程、脚本行为、Viewer 可见性和网关性能均须通过 V4 独立运行验证后才能确认。
