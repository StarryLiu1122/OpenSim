# Region Lab 版本路线与实施计划

更新日期：2026-09-15。当前开发版本：V3.1 / 0.3.1。

## 1. 目标与阶段调整

项目目标是逐步重建 OpenSim 的区域、地形、对象、资产、交互和持久化能力，并为后续智能体提供可验证的操作接口。真实感同时包含尺度、空间可达性、碰撞行为、光照材质和状态连续性，不能仅以画面效果衡量。

根据本轮需求，V3 优先实现真实尺度场景、可操作对象与区域环境。上一版计划中的“V3 数据库持久化”调整到 V4；原版行为对照仍作为后续数据兼容工作的前置条件。这次调整不意味着数据库或原版运行基线已完成。

| 版本 | 主题 | 当前状态 |
| --- | --- | --- |
| V1 / 0.1.0 | 单区域、方块、角色、快照与命令接口 | 已交付 |
| V2 / 0.2.0 | 地形笔刷、拾取、统一历史与地形碰撞 | 已交付 |
| V3 / 0.3.0 | 场景环境、多类对象、门灯交互与格式迁移 | 已交付 |
| V3.1 / 0.3.1 | 对象组合、静态 GLB 资产和性能基线 | 已实现，见实施清单与验证记录 |
| V4 | 原版运行对照、存储抽象与数据库 | 待实施 |
| V5 | 权威区域服务与双客户端同步 | 待实施 |
| V6 | 身份、库存、受控行为与智能体试点 | 待实施 |

## 2. V3：空间、环境与交互

| 工作项 | 实现范围 | 验收方式 |
| --- | --- | --- |
| 区域示例 | 256×256 米高度场、湖岸、道路、庭院、展馆与室内陈设 | 启动新世界，角色由道路进入建筑 |
| 对象类型 | 方块、圆柱、球、伸缩门、树木、路灯 | 创建、变换、删除、碰撞、恢复 |
| 表面表达 | 纯色、混凝土、砖、木材、金属；程序地表材质 | 材质选择、实际渲染、保存恢复 |
| 区域环境 | 固定太阳时刻、水位、水面开关、雾密度与网格显示 | 参数校验、撤销、重做、恢复与日夜截图 |
| 交互状态 | 门开启/关闭、灯开启/关闭；编辑按钮与漫游 E 键 | 门洞真实通行、灯光节点变化、距离约束 |
| 数据升级 | 世界格式 1 → 2；旧格式先验证再补齐字段 | V1/V2 实际样本、原文件不改写、保存后保留原备份 |
| 模块整理 | 分离内置对象适配、环境适配、示例生成与界面面板 | 界面、批处理共用 WorldService |

V3 的真实感属于程序化场景验证。尚未包含摄影测量、扫描纹理、真实城市模型、天气模拟、水体动力学或完整物理材质。建筑由独立物体组成，尚不是 OpenSim 连体物体。

## 3. V3.1：对象组合与静态资产

已完成根/子部件关系、局部变换、组命令、多选与组合面板；新建展馆由 15 个部件组成一组，门灯保留独立状态。GLB 入口限定静态三角网格、不透明 PBR 参数和内嵌 PNG，提供原始建筑、长凳、树三个 CC0 样本。

世界格式升级为 3，资产内容随快照保存；以旧格式样本、真实碰撞、界面事件及跨进程恢复验证行为。新增固定日景和 243 对象夜景性能测量，原始结果不外推为大规模场景容量。

具体任务、取舍和验收见 [V3.1 实施方案](v3.1-implementation-plan.md)。下一步从原版两部件组合的运行对照开始，再整理存储契约；数据库实现仍归入 V4。

## 4. V4：原版对照与数据库

目标：获得可追溯的行为基线，并把现有区域保存扩展为可迁移、可恢复的存储实现。

| 顺序 | 任务 | 验收条件 |
| --- | --- | --- |
| 1 | 独立构建固定 OpenSim 源码与单区域实例 | 留存工具版本、配置模板、启动日志；不接触用户已有区域 |
| 2 | 对照原版区域、prim、地形、门灯脚本、库存及重启行为 | 对照表分别标明一致、近似、未实现；以实际操作补充源码分析 |
| 3 | 提取 Repository 契约，形成数据库 ADR | 明确区域、对象、组合、资产、修订和迁移边界；固定数据库版本 |
| 4 | 实现数据库仓储与快照导入导出 | ID、坐标、地形与交互状态往返一致；拒绝旧修订写入 |
| 5 | 验证事务、故障、备份与恢复 | 部分失败回滚；服务不可用时保留未保存状态；备份可独立恢复 |
| 6 | 完成部署文档与独立目录验收 | 新目录按文档安装、初始化和运行，无固定凭据 |

PostgreSQL 是评估候选，服务语言与框架在 ADR 中确定。现有 GDScript 原型、Godot/Jolt 与原版 C# 参考代码继续保留；不进行缺乏具体收益的整体语言替换。

## 5. V5：双客户端与服务端权威状态

目标：两个客户端能够观察和编辑同一持久化区域。

- 将世界操作校验与最终状态移入无界面的区域服务。
- 定义世界世代、修订、命令确认、增量和完整快照协议。
- 验证冲突编辑、重复发送、断线、重连和服务重启。
- 同步角色、对象、地形、环境和行为状态。
- 记录双客户端收敛结果与可复现的延迟、资源占用数据。

现有进程内请求缓存、固定本机身份及文件指纹检查不构成网络一致性或身份认证方案。完成条件是客户端断开后服务仍能保存，重连后状态收敛，并发编辑有明确结果。

## 6. V6：库存、行为和智能体

先建立账户会话、库存条目、归属及最小权限，再开放受控工具。

首个智能体任务建议为“进入展馆、查询指定物体、操作门灯并报告结果”。工具只允许查询与已定义的命令，不执行任意生成脚本。为超时、取消、重复调用、权限拒绝和任务失败设置可复现测试。

门灯的内置状态机是行为接口的起点，不能直接视为 LSL/OSSL 兼容层。完整脚本语言、Firestorm 协议、跨区域和 Hypergrid 需另立专题。GameFactory 继续作为接口封装、开发任务组织和分层验收的参考，不作为已集成的大模型运行系统。

## 7. 发布要求

每个版本同时提交代码、数据契约、安装启动说明、自动化检查和实际渲染证据。旧数据升级有固定样本，失败操作不改变有效状态，测试只使用独立路径。文档明确区分已经实现、已经验证和计划中的内容。

不以测试条目数量替代功能质量，也不以单张截图推断性能或真实世界精度。工期在任务输入、资产和验收条件确定后估算。
