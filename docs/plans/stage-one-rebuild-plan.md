# Region Lab 后续开发计划

更新日期：2026-09-14。当前版本：0.2.0。本文按可验收交付组织后续开发，版本完成以功能、测试和文档同时具备为准。

## 1. 当前基础

| 版本 | 已交付范围 |
| --- | --- |
| V1 / 0.1.0 | 单区域、角色漫游、方块编辑、快照保存恢复、基础命令与测试 |
| V2 / 0.2.0 | 四种地形笔刷、地表拾取与预览、统一撤销重做、共享地形网格与碰撞、V1 存档兼容 |

V2 的实现与验证见 [版本说明](../../prototype/docs/releases/v2.md)、[使用说明](../../prototype/README.md) 和 [验证记录](../../prototype/docs/verification.md)。区域仍为本机单用户，尚无数据库服务和网络同步。

原版 OpenSim 固定源码的构建及行为对照尚未完成。现有概念映射来自源码分析，后续应通过原版实例补充行为证据。

## 2. V3：运行基线与数据库持久化

目标：建立原版行为对照，并将区域保存恢复扩展为具有事务与迁移能力的持久化服务。

| 编号 | 工作项 | 交付物 | 验收条件 |
| --- | --- | --- | --- |
| V3-01 | 在独立目录构建固定 OpenSim 源码，配置单区域实例 | 工具版本、构建脚本、运行配置模板及日志 | 从新目录完成构建和启动；不修改用户已有世界 |
| V3-02 | 对照角色移动、物体变换、地形修改及重启恢复 | 行为对照表、样例世界与差异记录 | 每项说明原版行为、原型行为及是否保持兼容 |
| V3-03 | 设计 Repository 接口与数据库模式 | ADR、实体关系、初始迁移及字段约束 | 区分区域修订、地形数据、物体实例和资产引用；数据库版本固定 |
| V3-04 | 实现数据库仓储与快照导入导出 | 数据服务、配置示例、迁移与导出工具 | 同一数据集可经文件与数据库往返，ID、坐标及高程满足一致性检查 |
| V3-05 | 实现保存事务与并发修订检查 | expected_revision 条件写入、错误协议与测试 | 旧修订写入拒绝；部分写入失败时事务回滚 |
| V3-06 | 验证服务故障、备份和恢复 | 故障测试、恢复步骤及验证报告 | 数据库不可用时保留未保存状态；备份可在独立实例恢复 |
| V3-07 | 完成部署及启动说明 | 环境锁定、初始化和服务启动脚本 | 新目录按文档运行，配置中无固定凭据 |

数据库优先评估 PostgreSQL。服务层可评估 Python/FastAPI；是否引入以及版本选择在 V3-03 决策记录中确定。区域物理仍由 Godot/Jolt 承担，逐帧计算不通过数据库或模型接口执行。

### V3 起始顺序

1. 先完成 V3-01、V3-02，形成可重复的原版行为基线。
2. 从现有 SnapshotRepository 提取保存、读取、错误返回及修订约定，编写仓储兼容测试。
3. 建立最小数据库模式，仅覆盖已有区域、地形、资产和物体。
4. 先验证命令行保存恢复，再接入图形客户端。
5. 完成故障和恢复验收后发布 V3，进入多人同步开发。

## 3. V4：服务端权威状态与双客户端同步

目标：一个区域服务进程维护最终世界状态，两个客户端能够观察和编辑同一区域。

| 工作项 | 验收条件 |
| --- | --- |
| 分离区域服务与客户端 | 服务端可无界面启动；客户端断开不影响服务端保存 |
| 定义连接、快照与增量协议 | 含世界世代、修订、对象标识和地形修改范围 |
| 将命令校验迁至服务端 | 客户端无法绕过服务端直接变更最终状态 |
| 实现冲突、重复命令和重连 | 并发编辑有明确结果；重连可从快照恢复当前状态 |
| 同步角色、物体和地形 | 两个客户端操作后收敛到相同修订与数据 |
| 记录性能 | 给出测试硬件、对象数、地形规模、同步延迟和资源占用 |

V2 的进程内请求缓存及全局修订不能直接作为完整网络一致性协议；V4 需单独定义跨连接和跨重启语义。

## 4. V5：身份、资产、库存与交互

目标：补足 OpenSim 世界语义中的基础实体关系。

- 建立账户会话与最小权限规则，分别约束区域和物体操作。
- 区分资产内容、资产引用及库存条目，记录归属与父对象关系。
- 支持一个经过校验的外部网格导入流程，明确单位、坐标、碰撞与引用。
- 实现一个内置交互行为，验证行为状态、事件及重启恢复。
- 建立权限、引用完整性及内容导入的回归用例。

完整 LSL/OSSL、Firestorm、连体物体、跨区域与 Hypergrid 作为独立兼容性专题，不并入最小库存实现。

## 5. 智能体与大模型接口

进入条件为世界操作、权限、修订和失败语义已稳定。首项任务采用有限工具集合：查询区域、查询对象、选择合法动作、检查执行结果。

模型调用运行在区域模拟循环之外。接入阶段需验证超时、取消、重复调用、权限拒绝及部分任务失败。界面与智能体使用相同的服务端命令入口，模型输出不能直接加载脚本或原生引擎资源。

GameFactory 的参考范围仍以操作封装、开发任务组织和验证方法为主。具体模型、SDK 和服务部署在该阶段单独固定版本。

## 6. 跨版本质量要求

| 项目 | 要求 |
| --- | --- |
| 数据兼容 | 保留上一版本样本，测试读取、编辑、保存与恢复；字段变更提供迁移说明 |
| 图形和物理 | 对可见几何、碰撞和高度查询做联合测试；新精度或算法假设有对应样例 |
| 历史与修订 | 失败操作不改变状态；修订、重试和撤销规则保持明确 |
| 发布范围 | README、版本说明和验证报告反映同一功能状态 |
| 文档 | 使用稳定术语、参数表及可执行步骤，区分需求、实现和验证结论 |
| 证据 | 报告记录环境、命令、结果及限制；截图只作为界面审阅材料 |

当前不设置未验证的固定工期。每个工作项开始时确认输入条件和依赖，完成后以验收结果更新计划。
